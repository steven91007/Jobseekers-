# c73d181 Support multi-location search, newest-first sort, and Excel export

## Summary
Location can now be a comma-separated list such as "Berlin, Hamburg, Munich". search_jobs_strict splits it, runs one guest-API search per location through a new _search_one_location helper that shares a ScrapeResult and a seen-id set for deduplication, requests LinkedIn's newest-first ordering with sortBy=DD, and finally sorts the merged list by posted_date descending. The CLI gains an optional Excel export (openpyxl) with bold headers, column widths, a frozen header row and clickable job links, and the Discord command descriptions document the multi-location syntax.

## Why
LinkedIn's guest search accepts only one location per request, so users tracking several cities had to create several subscriptions. Newest-first ordering makes the daily push surface fresh postings, and the Excel export gives CLI users a shareable report.

## Risks
Each extra location multiplies requests and therefore block risk; max_results is a total cap, so earlier locations in the list can starve later ones. The client-side sort relies on posted_date strings being comparable ISO dates. Fetch limits are now per location rather than per search.
