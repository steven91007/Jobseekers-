# 953d1c9 Add MCP server for job search, visa checks, gitkb and bot status, traced in Langfuse

## Summary
Adds an MCP server (python -m mcp_server, mcp SDK 2.x over stdio) exposing 11 tools: LinkedIn search, job detail and visa checks; gitkb search/show/log/history plus pending/import; and a read-only view of the Discord bot's subscriptions and run status. Each tool call is traced to Langfuse as one trace with typed, stably named observations. The server is registered for Claude Code in .mcp.json and launched through uv.

## Why
Lets agents such as Claude Code call the project's core capabilities directly instead of going through the CLI, the Discord bot or the file-based /gitkb flow, with observability in Langfuse as the user requested.

## Risks
requirements.txt now pins mcp>=2.2 which needs Python 3.10+, so pip install on Python 3.9 fails. Agents can call LinkedIn far faster than people do; a process-wide throttle (MCP_LINKEDIN_MIN_GAP) and result caps mitigate but do not remove IP-block risk. Flushing Langfuse after every tool call adds one HTTP round trip per call. gitkb_pending canonicalizes every pending commit before slicing to the limit.

Add MCP server for job search, visa checks, gitkb and bot status, traced in Langfuse

`python -m mcp_server` serves 11 tools over stdio and is registered in
.mcp.json for Claude Code (launched through uv, Python 3.13):

- search_jobs / get_job_detail / check_visa wrap linkedin_scraper and visa.
  The visa check runs only the offline rules and returns the description
  of undecided postings so the calling model judges them itself; the
  server needs no LLM key. All LinkedIn calls share one throttle, result
  sizes are capped, and blocks surface as "do not retry" tool errors.
- gitkb_search / show / log / history read the knowledge base;
  gitkb_pending + gitkb_import_summaries replace the pending.json /
  summaries.json round trip (gitkb.summarize.parse_summaries takes the
  decoded object). A missing index.db is rebuilt from the notes.
- list_subscriptions / bot_status open the bot database read-only.

Langfuse: one trace per tool call with typed, stably named observations,
session id per server process, masking of emails/phones/keys, linking to
the client's trace when _meta carries a traceparent, and the SDK's own
OTel server spans filtered out. Every call flushes because MCP clients
kill the server without warning at session end, which lost traces.

tests/test_mcp.py covers the tools with a fake LinkedIn, the protocol via
an in-process client, the gitkb round trip, the read-only bot view, and
the trace tree via an in-memory span exporter.
