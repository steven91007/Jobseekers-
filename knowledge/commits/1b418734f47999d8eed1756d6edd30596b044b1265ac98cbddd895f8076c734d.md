# 8dc875c Align Langfuse tracing with Langfuse best practices (#3)

## Summary
Reworks jobagent's Langfuse tracing to follow Langfuse's best practices: stable verb-first observation names in NAMES with run-specific values in metadata, specific observation types (retriever lookups, chain per scored job, agent for the research loop), meaningful root input/output, reasoning summaries on generations, web_search sources, export-time masking and a production default environment. It also fixes orphaned job-board spans, keeps agent LinkedIn searches inside the run's regions, and makes --max-score a budget for the whole run.

## Why
An audit against langfuse.com's best-practices page with a real OpenAI run showed dynamic span names, generic types, empty root I/O, missing thinking, unmasked contact data and orphaned spans.

## Risks
Observation names changed (jobagent.run -> run-job-search, score <key> -> score-job, ...), so dashboards or evaluators built on the old names stop matching. Requesting reasoning summaries may be refused for some orgs; the client falls back automatically.
