# 38c3d0b Refactor LinkedIn job id/URL parsing and use English job-type labels

## Summary
Refactors job-id extraction in the LinkedIn scraper into helpers that first read data-entity-urn and then fall back to the card link's href, understanding both the currentJobId query parameter and /jobs/view/<slug>-<id> paths. Job URLs are now always built canonically from the id, get_job_detail rejects non-numeric ids, the search loop stops at fetch_limit, and JOB_TYPE_LABEL values plus user-facing strings switch from Chinese to English. Chinese comments and docstrings are removed and formatting is normalised.

## Why
LinkedIn cards do not always carry data-entity-urn, so the old code skipped jobs; parsing the href recovers them. English labels prepare the module for reuse outside the Chinese CLI (the Discord bot arrives two commits later).

## Risks
Users of the CLI now see English job-type labels from this module unless main.py maps them (main.py keeps its own Chinese JOB_TYPE_LABEL). The tracking parameters in LinkedIn's original href are discarded in favour of the canonical URL.

## Files
- `linkedin_scraper.py` (M, +79/-50): Adds JOB_VIEW_RE, _build_job_url, _extract_job_id_from_href and _extract_job_id; search_jobs uses them, bounds the loop with start < fetch_limit and drops the redundant truthiness checks on work_type/job_type; get_job_detail validates the id; labels, error messages and the missing-description text become English.
