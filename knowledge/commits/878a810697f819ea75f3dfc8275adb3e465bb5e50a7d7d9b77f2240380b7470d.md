# b705335 Add gitkb: sha256-named commit knowledge notes indexed in SQLite

## Summary
Adds gitkb, a knowledge base of the repository's git history. Each commit becomes a Markdown note and each file change inside it becomes another, all named by the sha256 of the exact canonical text (commit header plus diff from fixed git diff-tree flags) that the note describes. A gitignored SQLite index with FTS5 links commits, files and notes and is rebuilt from the notes on demand. Summaries are written by Claude Code in-session through a pending/import flow (a /gitkb slash command documents it); no LLM API is called. The commit ships the package, an offline test suite, and real notes for all seven earlier commits.

## Why
The repository had no record of why each change was made beyond commit messages. The user wanted per-commit and per-change LLM-written summaries, content-addressed filenames, notes committed to git with a rebuildable local index, and explicitly asked that Claude Code write the summaries rather than an API.

## Risks
Hashes depend on git's diff output staying byte-stable; a future git version or changed caps would produce new hashes (the recipe string in each note makes that detectable). Notes under knowledge/ are excluded from summarization by default, so a commit that only touches notes yields header-only change notes. Requires Python 3.10+ like the rest of the project; FTS5 must be present in the Python's SQLite.
