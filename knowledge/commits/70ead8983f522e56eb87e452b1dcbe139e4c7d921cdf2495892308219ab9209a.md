# ae607ef Harden LinkedIn scraper with strict entry point for unattended use

## Summary
Hardens the LinkedIn scraper for unattended use. A new search_jobs_strict returns a ScrapeResult whose Outcome explains why a scrape produced its result count (OK, EMPTY_OK, EMPTY_SUSPICIOUS, PARSE_DRIFT, BLOCKED, RATE_LIMITED, TRANSPORT_ERROR), with typed exceptions for hard failures. HTTP goes through a shared _fetch with session reuse, split connect/read timeouts, at most three attempts with jittered backoff, Retry-After handling, and no retries on 403/999/authwall pages. A whole-operation deadline is enforced inside the sync function. search_jobs becomes a thin forgiving wrapper for the CLI. The commit also adds .gitignore, .env.example and the Discord bot dependencies.

## Why
The old search_jobs returned an empty list for blocked, broken-selector and genuinely-empty cases alike. A scheduled bot needs to tell those apart or it posts nothing and looks healthy forever. The in-function deadline exists because asyncio.wait_for cannot cancel a thread. Retrying blocks escalates soft rate limits into multi-hour IP bans.

## Risks
PARSE_DRIFT detection depends on li cards still being present when selectors break. get_job_detail now has a fixed 60 second budget. The bot config surface (.env.example) is committed before the bot code itself, so the two must stay in sync.

Harden LinkedIn scraper with strict entry point for unattended use

Adds search_jobs_strict(), which classifies *why* a scrape returned the
number of jobs it did, and reimplements search_jobs() as a thin forgiving
wrapper over it so the CLI behaves exactly as before.

Motivation: the old search_jobs() returned [] for "blocked", "selectors
renamed" and "genuinely no jobs" alike. That is fine for a CLI with a human
watching, but a scheduled bot would post nothing and look healthy forever.

- Outcome taxonomy: OK / EMPTY_OK / EMPTY_SUSPICIOUS / PARSE_DRIFT /
  BLOCKED / RATE_LIMITED / TRANSPORT_ERROR
- PARSE_DRIFT is the canary: real HTML with real cards but zero usable job
  ids means a selector rename, not an empty result set. Detecting it needs
  raw_card_count alongside len(jobs), which the old return type could not express.
- Session reuse, (5, 15) timeouts, <=3 attempts, 2/6/15s jittered backoff
- 403/999/authwall are never retried; retrying a block escalates a soft
  rate-limit into a multi-hour IP ban
- Whole-operation deadline enforced *inside* the sync function, because
  asyncio.wait_for around a thread cannot actually cancel the thread

Also adds project scaffolding: .gitignore (no .env/db/logs in git),
.env.example, and the bot dependencies. tzdata is required, not optional --
Windows ships no IANA database and ZoneInfo("Asia/Taipei") raises without it.
